# Сводка реализованных функций

## Обзор проекта
**One Step** — веб-приложение на Next.js для борьбы с прокрастинацией. Пользователь описывает задачу, которую откладывает, и получает один конкретный выполнимый шаг на 10 минут.

---

## 🎨 Frontend (app/page.tsx)

### Компоненты и состояние

#### Состояние (React Hooks)
- `thought` (string) — текст, который вводит пользователь
- `step` (string) — сгенерированный шаг (по умолчанию "—")
- `loading` (boolean) — индикатор загрузки при запросе шага
- `isSpeaking` (boolean) — индикатор процесса озвучки
- `audioUrl` (string | null) — URL созданного аудио-объекта

#### Функции

**1. `handleGetStep()`**
- **Назначение**: Получает шаг от API на основе введённой мысли
- **Логика**:
  - Устанавливает `loading = true`
  - Отправляет POST-запрос на `/api/step` с `thought`
  - Получает ответ и обновляет `step`
  - Обрабатывает ошибки
  - Сбрасывает `loading = false`
- **Триггер**: Нажатие кнопки "Get one step"

**2. `handleSpeak()`**
- **Назначение**: Озвучивает текущий шаг через ElevenLabs API
- **Логика**:
  - Проверяет наличие шага
  - Устанавливает `isSpeaking = true`
  - Отправляет POST-запрос на `/api/voice` с текстом шага
  - Проверяет Content-Type ответа (должен быть audio)
  - Создаёт blob и URL для аудио
  - Освобождает предыдущий audioUrl (если есть)
  - Проигрывает аудио через `Audio` API
  - Обрабатывает ошибки с детальными сообщениями
  - Сбрасывает `isSpeaking = false`
- **Триггер**: Нажатие кнопки "🔊 Play"

**3. `useEffect` (очистка аудио)**
- **Назначение**: Освобождает память при размонтировании или изменении `audioUrl`
- **Логика**: Вызывает `URL.revokeObjectURL()` для предотвращения утечек памяти

#### UI элементы
- Текстовое поле (`textarea`) для ввода мысли
- Кнопка "Get one step" (активна только при наличии текста)
- Карточка с отображением шага
- Кнопка "🔊 Play" для озвучки (активна только при наличии шага)
- Кнопка "Done" для очистки формы

## 🔧 Backend API

### `/api/step` (app/api/step/route.ts)

#### Функции

**1. `isBad(step: string): boolean`**
- **Назначение**: Валидация шага на соответствие правилам выполнимости
- **Проверки**:
  - Наличие переносов строк (`\n`) → `true` (плохо)
  - Запрещённые слова: "plan", "think", "list", "motivat", "analyze", "break down" → `true` (плохо)
  - Фразы-заглушки: "phrase about", "sentence about" → `true` (плохо)
  - Длина больше 160 символов → `true` (плохо)
  - Слишком общие шаги: "open the document", "write a heading" → `true` (плохо)
  - Шаги без конкретики (например, "open your notes" без упоминания темы) → `true` (плохо)
- **Возвращает**: `true` если шаг не соответствует правилам, `false` если хороший

**2. `buildPrompt(thought: string): string`**
- **Назначение**: Формирует промпт для Gemini API с чёткими инструкциями
- **Структура промпта**:
  - Описание задачи: помощь в преодолении прокрастинации
  - Две части ответа: Explanation (одно предложение) и Step (одно предложение)
  - Строгие правила для Explanation: нейтральность, без советов, без "you"
  - Строгие правила для Step: конкретное действие, 10 минут, без планирования, макс 160 символов
  - Формат вывода: "Explanation:\n...\nStep:\n..."

**3. `callLLM(prompt: string): Promise<string>`**
- **Назначение**: Вызывает Gemini 3 Flash Preview API для генерации ответа
- **API**: `https://generativelanguage.googleapis.com/v1beta/models/gemini-3-flash-preview:generateContent`
- **Параметры**:
  - `temperature: 0.4` (низкая для более детерминированных ответов)
  - `maxOutputTokens: 200` (достаточно для полного ответа)
- **Обработка ошибок**: Логирует finishReason если ответ пустой
- **Возвращает**: Сырой текст ответа от Gemini

**4. `parseGemini(text: string): { explanation: string; step: string }`**
- **Назначение**: Парсит ответ Gemini и извлекает explanation и step
- **Стратегия парсинга** (многоуровневая):
  - Pattern 1: Стандартный формат с метками "Explanation:" и "Step:"
  - Pattern 2: Если Step не найден, ищет текст после Explanation
  - Pattern 3: Альтернативные варианты разделения
- **Очистка**:
  - Удаляет кавычки вокруг текста
  - Удаляет префикс "Today (10 min):" если модель его добавила
- **Возвращает**: Объект с `explanation` и `step`

**5. `POST(req: Request)`**
- **Назначение**: Генерирует один выполнимый шаг на основе мысли пользователя через Gemini 3 Flash Preview
- **Входные данные**: `{ thought: string }`
- **Логика**:
  - Извлекает `thought` из тела запроса
  - Строит промпт через `buildPrompt()`
  - **Система ретраев**: До 3 попыток генерации шага
    - Вызывает `callLLM()` для получения ответа
    - Парсит ответ через `parseGemini()`
    - Проверяет шаг через `isBad()`
    - Если шаг валидный → использует его и прерывает цикл
    - Если шаг плохой → логирует причину и пробует снова
  - Сохраняет explanation из первой успешной попытки
  - Если все попытки неудачны → возвращает FALLBACK ("—")
  - Логирует сырой ответ Gemini в dev-режиме для отладки
- **Выходные данные**: JSON с полями `{ explanation: string, step: string }`

### `/api/voice` (app/api/voice/route.ts)

#### Функции

**1. `POST(req: Request)`**
- **Назначение**: Конвертирует текст в речь через ElevenLabs API
- **Входные данные**: `{ text: string }`
- **Логика**:
  - Валидирует входные данные (проверяет наличие и тип `text`)
  - Получает `ELEVENLABS_API_KEY` из переменных окружения
  - Проверяет наличие и валидность ключа
  - Формирует запрос к ElevenLabs API:
    - Voice ID: `21m00Tcm4TlvDq8ikWAM` (дефолтный)
    - Настройки: `stability: 0.5`, `similarity_boost: 0.5`
  - Отправляет POST-запрос на `https://api.elevenlabs.io/v1/text-to-speech/{voiceId}`
  - Обрабатывает ошибки API с детальными сообщениями
  - Возвращает аудио в формате `audio/mpeg`
- **Выходные данные**: 
  - Успех: `audio/mpeg` (ArrayBuffer)
  - Ошибка: JSON с полями `error`, `details`, `status`
- **Обработка ошибок**:
  - 400: отсутствует или неверный `text`
  - 500: отсутствует API ключ
  - Другие: ошибки ElevenLabs API с деталями

### Используемые технологии

- **Типизация**: TypeScript

## 🔄 Как работает приложение

### Поток данных:

1. **Пользователь вводит мысль** → `thought` сохраняется в state
2. **Нажатие "Get one step"** → `handleGetStep()` отправляет POST на `/api/step`
3. **Backend обрабатывает запрос**:
   - Строит промпт с инструкциями для Gemini
   - Вызывает Gemini 3 Flash Preview API
   - Парсит ответ (explanation + step)
   - Валидирует step через `isBad()`
   - Если плохой → повторяет до 3 раз
   - Возвращает `{ explanation, step }`
4. **Frontend получает ответ** → обновляет state и отображает в UI
5. **Нажатие "🔊 Play"** → `handleSpeak()` отправляет POST на `/api/voice`
6. **Backend генерирует аудио** → ElevenLabs API конвертирует текст в речь
7. **Frontend проигрывает аудио** → создаёт Audio объект и воспроизводит
